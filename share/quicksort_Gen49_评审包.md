## A. 背景与诚实声明

**这是什么**：一个泛型 `T: Ord` 的原地、不稳定、零分配快速排序，Rust 实现。
仓库是「快排进化论」项目：从教科书朴素版起迭代 51 代。
与 Rust 标准库 `slice::sort_unstable`（rustc 1.96 起内核为 ipnsort）对标。

**性能口径（第四版最重要的修正——按规模区间拆分）**：
外部第三家用 11 分布 × 4 规模分离测量定论：此前所有分数分歧 **100% 源于
规模区间 n**，不是分布集构成。本仓库实测（bench scale-ext informational 行）：

| 规模区间 | 口径 | 几何平均 |
|---|---|---|
| n ≤ 10k（23 case 原集，7 分布 × 100/1k/10k） | 热端（同数据重复） | **~0.95~1.01x（≈打平）** |
| n = 1e5/1e6（同上 7 分布，规模扩展行） | 热端 | **0.836x（慢约两成）** |
| n = 1k/10k | 冷端（每轮新数据） | random **0.48~0.56x**、few-unique 0.46~0.58x |

- random 单项：1k/10k 热端 ~0.9x，1e5/1e6 0.60~0.64x
- few-unique 单项离散极大（k=2 @1e6 同实例 4.5x 落后 vs 新实例 0.73x 领先）
- 唯一全规模确定的赢项：**nearly-sorted（1e5/1e6 仍 1.31~1.35x）**
- 热身效应只存在于 n ≤ 1e4，且**std 同样热身**（random 1k：ours 3.4x、
  std 1.6x）；cache 维度完全无效应（flush/warm = 1.00x 全部 44 组）
- **引用规则：任何总分都必须绑定（规模区间 × 口径 × 分布集）三要素。**

**作者方已知的设计取向**（可能带偏见，请独立判断）：
- pdqsort/ipnsort 族机制 + 自己的信号路由（粗糙预筛三态 × partial insertion
  两段式 × 双分区器 × 坏分区 DNF 升级 × 退化分区强粉碎 × 深度预算 heapsort）
- 每个参数（CUTOFF=32 / NINTHER_MIN=64 / PARTIAL_LIMIT=8 / UNBALANCED=8 /
  SPARSE=48 / DEPTH_CONST=3）都经过多轮扫描确认，非默认值拍脑袋
  （注意：三家外部评估中一家报 CUTOFF 40-48 更优 ~15%，另一家判噪声淹没
  不可判定——**该参数在外部 harness 上未被证实，欢迎再测**）
- 5 次尝试 BlockQuicksort 方向均实测更差。旧归因（带宽/净指令数）已被外部
  评估部分推翻——更可能是我们的分区写侧流量过大（每元素 2 读 2 写），
  真实修法疑为 **cyclic Lomuto（每元素至多一次写）**，列入下一代候选

**诚实声明（截至 Gen 51 的实测口径）**：
1. panic 路径：曾被发现 cmp panic 时洞式插入 double-free（对 Drop 类型），
   已用 InsertHole guard 修复；三家外部独立注入验证累计约 16 万注入点，
   每元素恰好 drop 一次。
2. **Miri 已跑**：曾抓出一处真实 Stacked Borrows UB（`InsertHole::shift`
   双取指针），已一行修复；修复后 SB+TB 双模型、clean 与 panic 注入路径
   全部 0 UB（修复前版本红→绿复验过）。
3. 非全序 `Ord`：行为为「静默产出无意义结果」。非**自反**比较器
   （`cmp(x,x) != Equal`，比非传递更窄）曾构造出 hoare 左扫描越界
   **panic** 见证（公开 API，n >= CUTOFF+1，安全索引边界检查非 UB）；
   Gen 51 已给双扫描加显式边界：不再 panic/挂起、多重集守恒、合法 Ord
   下零行为变化（金丝雀零成本）。
4. 复杂度与可维护性：热路径单函数 + 7 条路由路径。外部一致认为
   「对生产库过重」；消融实验证明整层不能砍（sorted/reverse 会退化
   20~44 倍），但 Hoare 选择子分支在 organ-pipe/two-run 等分布上
   可能是净负收益（一家实测消融更快 12~33%），是明确的调优目标。
5. 泛型通用性：无 Copy/size_of 特化。外部两家证实「特化只解释一部分」：
   元素变宽（8B→128B）不缩小差距、工作集超缓存 8 倍比值纹丝不动
   ——random 差距不随内存压力变化。
6. **重复密集输入种子敏感**：bench 的 few-unique 用单一固定种子。
   9 种子体检（n=10k）0.90x；但外部实测该敏感性**强烈依赖规模**：
   k=2 跨种子跨度 n=10k 时 1.76x、n=1e6 时 **7.13x**（双峰：是否触发
   DNF 升级，5 倍悬崖）。翻转点已定位：两路分区在低基数数据上「全有或
   全无」，失衡后 DNF 双重全扫。若做基准，重复类分布必须多种子 × 多规模。
7. **热身偏差有规模边界**：只存在于 n ≤ 1e4（n≥1e5 归零），且 std 也受影响
   （random 1k：ours 3.4x、std 1.6x，ours/std 差 ≈2 倍）。cache 维度无效应。
8. `panic = "abort"` 只影响作者自测的 workspace；已量化其利己偏差
   （+3.3% @1M / +4.9% 总分）。

**测量可靠性声明**：作者记录过 "编译后立即测 bench" 会造成 ~17% 的相位污染
假回退，正确做法是同 session 交替 A/B。评估测得的绝对数字请以此为戒。

**第一版评估的历史记录**（供参考哪些已翻篇）：
- 三家外部评估正确命中：SB UB（已修）、few-unique 单种子假象（已自证并撤回）、
  「0.97x 打平」不可复现（已定位为规模+口径问题并双口径化）、hoare 非自反
  越界 panic 见证（已加固）、同数据重复热身偏差（已量化，范围限 n≤1e4）、
  cyclic Lomuto 无效（两家金丝雀，已入死路）、「比较次数优先」被 organ_pipe
  反例推翻（差额真因是内存趟数）
- 三家外部评估未命中/说错：怀疑我们 bench 有缺页污染（实际我们的计时区外
  一次性分配，干净）；「std 几乎不受热身影响」（实际 std 也有 1.6x，只是
  我们 3.4x 更大）；few-unique 的各种单点读数都是规模/种子特定，均不可作结论

## C. 建议的验证方法

### C1. 正确性（差分测试，最小编码量）
```rust
fn main() {
    for n in [0usize, 1, 2, 3, 4, 5, 31, 32, 33, 63, 64, 65, 127, 128, 129,
              1000, 10_000, 100_000] {
        let mut v: Vec<u64> = (0..n).map(|i| (i.wrapping_mul(2654435761) % 997) as u64).collect();
        v.sort_unstable();
        quicksort(&mut v);
        assert!(v.windows(2).all(|w| w[0] <= w[1]), "random n={n}");
    }
    // 分布：sorted / reverse / all-equal / few-unique / organ-pipe / two-run / 锯齿波
}
```

### C2. panic 安全（该实现的核心声明）
实现一个会 panic 的 `Ord`（如某元素比较时 panic）+ 一个记 drop 次数的
`Drop` 类型，`catch_unwind` 后断言：**每个 id 恰好被 drop 一次**。
（本仓库 tests/panic_safety.rs 有两个已验证用例，但请独立重写验证。）

### C3. 非全序安全性
用 NaN 包装型或不传递的 cmp，断言「顶多 panic，不 UB」（可配合 Miri）。

### C4. 性能建议（如做基准）
- 对照：`slice::sort_unstable` 同机器同编译器；注意 Rust 1.81 后它是 ipnsort
- **规模比分布更重要**：n≤10k ≈ 打平、n≥1e5 慢两成——两套都测并绑定报告
- **冷/热口径**：同数据重复排 k 次有热身（n≤1e4 时 ours 3.4x / std 1.6x），
  冷数据（每轮新数据）才是真实使用场景的代理；n≥1e5 热身归零
- 必须交替测量（ours/std 交替、每侧多轮取中位）；禁止编译后立即测量
- 重复密集分布（few-unique 族）必须**多种子 × 多规模**（n=10k 跨度 1.76x，
  n=1e6 跨度 7.13x，双峰；同实例与新实例可差 6 倍）
- 建议规模点 n = 1e3/1e4/1e5/1e6 × 分布：random / sorted / reverse /
  all-equal / few-unique(k=2/5/8) / organ-pipe / nearly-sorted / two-run

### C5. 可重点质疑的方面
1. **三路直进（Gen 52 首选候选，未做）**：branchless Lomuto 在低基数数据上「全有或全无」——失衡后整段重跑 DNF 双重全扫，是 few-unique 落后与 5 倍种子悬崖的共因。外部第三轮定论：省的是**一整趟内存搬运**不是比较（organ_pipe 少用 4% 比较却慢 43%）——所以三路直进的收益性质比预想的更值钱。在 branchless 循环里顺带统计等值数（pdqsort/ipnsort 同款）能否同时修掉两者？正确性怎么门禁？
2. **Hoare 路由重标定 + organ-pipe 专项**：外部消融实测 organ-pipe/two-run/reverse_random/interleaved 上「剥掉整个自适应层反而快 12~33%」。具体建议：`descending_run_at_bail` 命中时**跳过** `scramble_patterns`（专门为 organ-pipe 设计的分支，不该再对它做 O(n) 分块轮换）；`SPARSE_DESCENT_BAIL=48` 的极性/阈值是否标定错误？（注意：整层不能砍，sorted/reverse 会退化 20~44 倍。）
3. **CUTOFF 协议**：外部两家结论相反（一家 40-48 弱优 ~3%，一家用对照组证明伪信号大于真效应、判不可判定——第一家已接受质疑）。按「每值独立二进制 + 同批对照组分布 + 仅当对照落在 1.00±0.03 才信」能判定吗？
4. ~~比较次数优化~~ **该方向已被外部反例推翻**（比较比与时间比相关性为零：organ_pipe −4% 比较却 +43% 时间；nearly_sorted +20% 比较却 −1% 时间）。+18~22% 比较劣势属实但不是杠杆，勿投入。
5. `insertion_with_budget` 的 `bail_pos` 与 partial 的「第 9 下降沿」是**两个语义**（nearly-sorted 上后者占 ~74%）——阈值到底是按哪个信号标定的？分源重标定值多少？
6. heapsort 兜底常数极差（实测 0.113x，慢 8.9 倍）且 `break/scramble_patterns` 种子只依赖 len（确定性防御可被针对性绕过）。深度预算独立保证渐近界，这是否可接受？
7. 还能找到第四处 unsafe/契约问题吗？（前三处：panic double-free、shift SB、hoare 跑飞，均已修；外部 12,648 组逐字节等价 + 42,000 组非自反均未再发现问题）
8. **热身偏差的规模边界与机制**：已确认只存在于 n≤1e4 且 std 也热身。分支预测器假说之外还有什么机制？批内交替换新数据能否得到对双方都公平的热端口径？
